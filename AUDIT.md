# Performance, smoothness and correctness audit

Lighthouse (mobile profile, throttled), before → after, home page: Performance 94 → 98, Accessibility 100, Best Practices 96 → 100, SEO 100. CLS 0, TBT 20 ms, LCP 2.3 s. Test route: Performance 100, Best Practices 100.

## What changed
- Fonts self-hosted (Jost variable + Cormorant Garamond, latin subset, woff2, `font-display: swap`, preloaded). No Google Fonts requests.
- Images converted to WebP (flower 516 KB → 80 KB, logo 135 KB → 13 KB, hero 26 KB → 10 KB); responsive `srcset` for the hero flower; width/height set; lazy loading below the fold; hero flower preloaded on the home route only.
- Server: gzip, in-memory minified CSS/JS (esbuild, optional), CSS inlined into the home document (no render-blocking request), long cache headers for fonts/images, ETag revalidation for CSS/JS, `sw.js` offline cache for static assets (never `/api`).
- Motion: every transition/animation uses one curve `cubic-bezier(.22,1,.36,1)`, 150–600 ms (ambient loops excepted), with two deliberate exceptions that each have ONE shared token in `:root`: (1) every underline / bar sweep — nav underline, value-card underline, progress bar, quotient mini-bars, score marker — uses `--sweep-dur: 1.2s` with `--sweep-ease: cubic-bezier(.4,0,.2,1)` (slow and even, so the left-to-right movement is visible; the nav underline measures 0 → 100 % over about 1 s); (2) every card hover uses `--lift: -4px`, `--icon-pop: 1.1`, `--hover-dur: .4s` and `--shadow-hover` (lift 4 px, icon +10 %, shadow grows). Under `prefers-reduced-motion` the lift and icon scale are set to 0 / 1 and only the shadow changes.
- Glass: no blur nested inside blur; test cards are solid-translucent; `.lite` mode (≤4 cores, ≤4 GB, or Save-Data) and browsers without `backdrop-filter` get solid backgrounds.
- Correctness: a failed save now shows an error with **Try again** / **View my profile without saving** (before, it fell through silently); retries carry a `submissionId` so the server never writes a duplicate row; Excel is written before the JSON backup; progress bar has `role=progressbar` and exact `aria-valuenow`; step dots are `role=img` with a real label; locked nav links are `aria-disabled`, `tabindex=-1` and click-blocked; the footer attribution no longer causes sideways scrolling at 768 px; plan tip headings no longer skip a heading level; observers, timers and animation frames are released on every page change. Numerals use lining figures everywhere (`font-variant-numeric: lining-nums`), because Cormorant's default old-style "1" looks like a capital I.

## Loading, error and empty states (flower logo)
One component, the real logo mark (`img/huq-mark.webp`), is used for every non-content state: **loading** (full-screen splash that only appears if the app takes more than 300 ms, so fast loads never flash it; it fades out when the first page is on screen), **loading failed** (if `app.js` cannot load, or nothing appears within 12 s, the splash turns into "This is taking longer than usual" with Reload), **saving** and **save failed** (logo on a cream disc, gold *Try again*), **404 route**, **no data yet** (Profile / Action Plan before the test is finished), **render error** (a page that throws shows "That page didn't load properly" instead of a blank screen), **offline / back online** (a toast under the nav) and **JavaScript off** (`<noscript>`). The server returns the same-looking HTML page for unknown URLs and server errors, and JSON (never HTML) for `/api` paths and malformed requests.

## Profile reveal (click-to-bloom)
The Profile page is gated: on arrival it renders only the title, one line of text and a closed flower with a "Click / Tap to reveal your profile" button (the button covers the whole flower, so the tap target is large; its accessible name is the visible text). The result is not in the DOM until the click, so nothing leaks to assistive technology, view-source or print before the reveal. After the click: bud opens (0 s) → real flower blooms (0.25 s) → flower glides left and the scores slide in (1.4 s) → the page opens upward to the overall score (2.3 s) → remaining sections (3 s). Only `transform` and `opacity` are animated for the flower and details (the flower move is a FLIP transform); two one-off exceptions use layout properties on purpose — the hero's `grid-template-rows` (0.9 s) and the card height (1 s) — because the page genuinely changes size. Leaving the page mid-reveal cancels every timer and observer; reduced motion skips the sequence entirely; low-end mode keeps the open animation but drops the idle breathing.

## Checks that pass (automated, Chromium)
Profile reveal: gate shown first and fully visible in 900 px and 657 px tall viewports; no scores, cards or tables in the DOM before the click; Enter on the focused button reveals; flower blooms, details, hero score, 8 cards, summary and buttons all present after; click replays the bloom; focus moves to the card and a live region announces it; revisiting Profile shows the closed flower again; leaving mid-reveal leaves no errors or leftovers; reduced motion shows everything at once with zero running animations; wording is "Tap" on touch devices and "Click" otherwise; no horizontal overflow at 320, 390, 768, 1024 and 1366 wide in either state. 
Direct URL to Profile/Plan shows the "No data yet" state (flower logo, progress so far, button to the test); an unknown route shows the 404 state; Next stays disabled until all 12 answered; progress = answered/96; back keeps answers; browser back/forward keeps the step and stepper; refresh keeps answers and resumes at the first incomplete step; whole 96-question test completed with the keyboard only; no console errors or warnings; no horizontal overflow at 320, 375, 768, 1024, 1440 and 844×390 landscape; zero running animations under `prefers-reduced-motion`; no `backdrop-filter` in print; real PDF export of Profile and Plan (no cut cards, no blur); scoring boundaries (28/29, 44/45, 228/229, 356/357), totals reconcile on 500 random answer sets, ties flag every top value; offline reload works.

## Not done / needs you
- Colour contrast: the bronze (#A27C3F) used for small labels and eyebrows is 3.7:1 on cream; WCAG AA needs 4.5:1. Left unchanged because it is a palette decision. Using rust (#A8450F, 6.4:1) for those small texts clears it.
- Firefox, Safari/iOS and real phones were not tested here (only Chromium is installed). Fallbacks for `backdrop-filter` and `-webkit-` prefixes are in place.
- Age/Gender/Role stay compulsory (you asked for that), unlike the brief's "optional".
- Not applicable to this build: React/Framer Motion items (memo, contexts, AnimatePresence), bundle splitting (no bundler; the admin page is server-side and never sent to visitors), SVG chart libraries (none used).
